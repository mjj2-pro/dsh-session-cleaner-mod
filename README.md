# dsh-session-cleaner（本地改造版）

> 给 DeepSeek Harness 补上「真删除」：**删得干净、能反悔、标题不骗人。**

**这是独立改造版，不是上游的镜像。** 底座来自 [jackxiao17/dsh-session-cleaner](https://github.com/jackxiao17/dsh-session-cleaner) v0.7.7（MIT），删除链路、标题读取、列表性能、界面文案都重做过。不合并上游、不跟上游同步。

- 版本：`0.8.1-mod.1`
- 适用：DSH 0.2.x（实测 0.2.2-rc.1 / rc.5）
- 许可证：MIT（见 [LICENSE](LICENSE) 和 [NOTICE](NOTICE)）

## 它解决什么问题

DSH 到 0.2.2-rc.1 为止**没有删除会话的功能**。侧栏 `···` 菜单只有 重命名 / 分叉 / 归档。而「归档」只是把 sessionId 塞进 `workspace.json` 的 `archivedSessionIds`，**磁盘上的日志、附件、投影缓存一个字节都不动**，而且单向不可逆。

同类插件在 `awesome-dsh-plugin` 里有 700 多个，做删除/回收站的超过 100 个。一个反直觉的观察：**star 数和质量负相关**——星多的功能堆得多、issue 也多（有 14 个 open issue 的、有首帧 1 MiB 卡死整块面板的、有默认模式就删用户产出文件的）。所以选了当时只有 7 star、但「不碰产出文件 + 子代理级联 + 清全部记账」三件都做对的底座来改。

### 用户的 8 条原始诉求 → 现在的实现

| 诉求 | 实现 |
|---|---|
| 要能删，删得干净（不能「页面看不见、磁盘还占着」） | 搬走日志目录 + 摘记账 + 清投影缓存行 + 清定时任务，四处都不留 |
| 不能动 AI 交付给我的文件 | 删除前列出产出文件，**默认全选、取消勾选即保留** |
| 要反悔期 | 自有回收站，15 天自动清理，恢复时**文件和会话一起回来** |
| 要批量删、按天分组 | 会话管理面板，按天分组 + 每组勾选框 + 空会话快捷键 |
| 父会话和子智能体一起删 | 级联整棵后代树（深度 8），列表里不单独显示子代理 |
| 要看出哪些是交付物、哪些是中间产物 | `present` 工具识别交付物（红色加粗），`write/edit` 等算中间产物 |
| 空白会话要能一次清掉 | `isBlank` 标记 + 「选中 N 个空会话」 |
| 界面别乱挡 | 侧栏底部按钮改成 48px 可拖拽悬浮球 |

## 这一版（0.8.1-mod.1）修的两个硬问题

### 1. 标题和用户改的名字对不上

**症状**：会话管理里的标题停在「第一句话截断」或很早的自动命名，用户后来手动改的名字看不到。实测 166 条列表里 **19 条错**。

**根因（不是猜的）**：旧实现只从日志末尾往回扫 **160 帧**找 `session/title`。但实测 181 个会话，最后一条标题大多落在**第 6–10 帧**（改得晚的在第 848 帧）。160 帧的窗口从尾巴往前根本够不到，于是悄悄退回头 6 帧里的第一版——**方向对了，范围错了**。

**做法**：

1. 本地解压，从末尾一直扫到第 6 帧，取最后一条 `session/title`（这才是用户改名时写下的那一条）。
2. 按 `mtime:size` 缓存结果：日志只会追加，键不变就说明标题没变。
3. 再落一份盘（`<dshHome>/dsh-session-cleaner/cache/titles.json`），DSH 重启后第一次打开也是毫秒级。
4. 宿主投影缓存只用来补「日志里压根没有标题事件」的空位——**它可能是旧值，不能覆盖日志**（实测 166 条里 9 条是旧的）。

**试过但放弃的路**：`sessionQuery.readTitleSnapshots(ids)`。它一次批量调用会把 `/list` 从 3.2 s 推到 **4.1 s**，第二次打开还是 3.8 s——内部要重扫持久化清单并冷读每个日志，比本地并发解压更慢，而且没有跨调用缓存。准确率确实 100%，但本地解压修好之后同样 100%，所以净亏，已从主路径移除。

### 2. 打开「会话管理」要等 3 秒

**实测拆解**（181 个日志 / 64 MB）：

| 做法 | 耗时 |
|---|---|
| 只读文件、不解压 | 71 ms |
| 串行解压全部日志找标题 | 3162 ms |
| 8 路并发解压 | 1668 ms |
| **现方案（16 路并发 + 磁盘缓存）** | **冷 284 ms，热 80–93 ms** |

所以瓶颈从来不是「文件大」，是**串行解压无关的帧**。做法：

- 读 header 一律 16 路并发（`mapLimit`）。
- 列表**不重复读同一个 header**：一次扫描拿到的 `header` / `artifact` 直接传给行拼装。
- 空会话判据用体积：`>= 2 KB` 必然发过消息，**连头 6 帧都不解**。
- 标题和目录体积都走同一个并发池。

### 3. 顺手修的两句假话

| 界面原文 | 实际 |
|---|---|
| 「回收站保留 **30 天**」 | 代码一直是 15 天，文案没改 |
| 「文件删除后**无法恢复**，也不在会话回收站里」 | 文件其实是搬进回收站，恢复会话时**原路搬回** |

第二句会让人以为勾选文件 = 永久销毁，反而不敢勾。

## 代码是怎么写的（给人看的）

### 两半架构

```
lib/index.js    宿主半（Node 进程内）：所有文件操作、路径校验、回收站
lib/client.js   浏览器半：菜单项、悬浮球、三个弹窗、中英语言包
```

两半靠 HTTP 路由通信（`/session-cleaner/api/*`）。零第三方依赖，两个文件约 3700 行。

### 「删除」到底是七步，顺序本身就是设计

```
1. teardownLive()        取消进行中的 turn、dispose agent
2. captureSession()      快照：原目录、工作区槽位、缓存行原文、置顶、归档、定时任务
3. previewSession()      读日志算出「交付物 / 中间产物」清单
4. writeMeta(prepared)   ⚠️ 先写快照，再动文件——崩溃才能对账
5. extractSession()      rename 目录 → 回收站；随后立即复核原路径已消失
6. storeSelectedFiles()  ⚠️ 必须在 5 成功之后。反过来会「文件没了、会话还在」
7. writeMeta(trashed)    更新快照为完成态
```

**为什么顺序不能改**：如果先删文件再搬目录，搬目录失败（Windows 文件被占用）就会得到最坏结果——文件没了、会话还在。现在的顺序保证最坏情况只会「少删」，不会「多删」。

### 崩溃对账不是「补删」，是「补齐或复原」

快照里的 `stage`（`prepared / trashed / incomplete`）是崩溃安全的核心。启动后对账按现场分三种：

| 现场 | 处理 |
|---|---|
| 快照写了但文件还在原位 | **撤销这次删除**（等于没删） |
| 文件已经在回收站 | 补上完成标记 |
| 回收站有目录但快照丢了 | 标成「孤儿」，只允许彻底删除 |

方向是**安全回退**，不是把漏掉的再删一遍。

### 安全边界

产出文件不是随便什么都能删：必须通过「真实路径（`realpath`，破软链）落在该会话 cwd 内」「不在 DSH 数据目录内」「是普通文件不是符号链接」，而且**必须在宿主自己重新扫描出的清单里**——前端伪造路径无效。

### 对抗「看起来更聪明」的办法：实测

这一版最重要的教训写在代码注释里：**优化前后各测一次**。第一版把「批量问宿主」放进主路径，逻辑上更正统，实测却让 3.2 s 变成 4.1 s。看起来更聪明的路径，可能更慢。

## 没做的（诚实清单）

| 限制 | 说明 |
|---|---|
| 没有单元测试 | 只有调试用的探针脚本；验收靠真实接口数据，不靠猜 |
| 批量删除不处理产出文件 | 逐个解压太慢；面板里已注明「要清文件请单个删」 |
| `im:xxx` 会话删不掉 | `assertSessionId` 拒绝冒号（装了飞书/企微这类 IM 插件才会遇到） |
| 超过 24 MB 的日志标题可能不准 | 只读头部，标题停在第 6 帧版本 |
| 定时任务只抄录不删 | 宿主不支持原样重建任务，删了回不来 |
| 侧栏不能插自定义分组 | `sidebar.workspaces` 是 single 洞，已被官方独占；「悬浮球 + 全屏面板」是上限 |
| 首次（删了缓存）仍是 284 ms | 更极致要拆成「列表接口 + 标题接口」渐进渲染，收益不值复杂度 |

## 装它

DSH 的插件分「宿主半」和「客户端半」，安装方式取决于你的 DSH 版本。当前推荐手动装：

1. 把整个仓库放到 `<DSH_HOME>/profiles/desktop/local/dsh-session-cleaner`。
2. 在 profile 的 `package.json` 里加依赖：

   ```json
   "dsh-session-cleaner": "file:./local/dsh-session-cleaner"
   ```

   并在 `dsh.profile.bundles` 里加 `"dsh-session-cleaner"`。
3. 在 profile 目录执行 `pnpm install`。
4. **重启 DSH**（宿主半改动必须重启，Loader 按包名缓存模块）。
5. 验证：`GET http://127.0.0.1:<端口>/session-cleaner/api/health` 返回 `{"ok":true,...}`。

> 目前还没上架任何插件市场索引，只能从 Git 仓库安装。
